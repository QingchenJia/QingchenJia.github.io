### 一、为什么推荐ContextMenuManager

Windows 电脑安装的软件多了，右键菜单往往也会越来越长：压缩工具、网盘、播放器、编辑器纷纷加入自己的入口，有些项目很少使用，有些甚至在软件卸载后仍然残留。

如果只是想隐藏几个不常用的菜单，逐个查找软件设置比较麻烦，直接修改注册表又容易找错位置。[ContextMenuManager](https://github.com/BluePointLilac/ContextMenuManager) 提供了更直观的操作方式：按文件、文件夹、桌面背景等场景列出菜单，通过开关控制显示，还能修改名称、图标和命令。

它是一款免费的 Windows 右键菜单管理工具，源代码公开。与功能庞杂的系统优化软件相比，它的功能集中在右键菜单，适合希望把菜单整理得简洁、顺手的用户。

我最推荐的使用方式是：**先隐藏不常用的项目，再补充少量真正需要的入口。** 通常不需要删除大量注册表项，也不必把所有功能都尝试一遍。

### 二、版本与系统兼容性

官方 README 明确列出的支持范围是 Windows Vista、7、8、8.1、10，支持 32 位和 64 位系统。发布版本较早，不应将其理解为已经完整适配所有新版 Windows 功能。

Windows 11 用户尤其需要区分两种菜单：

- **新版右键菜单**：直接右键时出现的简化菜单。
- **经典右键菜单**：通过“显示更多选项”等入口打开的传统菜单。

ContextMenuManager 主要围绕传统右键菜单的注册表与文件机制进行管理。Windows 11 上的效果应优先到“显示更多选项”中检查；不能保证它能编辑新版菜单中的全部项目，WinX 等功能也需要按当前系统实际情况验证。

### 三、哪些功能特别实用

#### 1.按场景启用或禁用菜单

右键一个文件、一个文件夹，或者文件夹里的空白区域，出现的项目可能完全不同。ContextMenuManager 将这些场景分开，便于找到真正需要调整的位置。

| 场景               | 可以怎样使用                         |
| ------------------ | ------------------------------------ |
| 文件               | 整理针对各种文件显示的通用入口       |
| 文件夹、目录       | 管理针对文件夹对象的打开、处理等菜单 |
| 目录背景、桌面背景 | 管理在空白处右键时出现的项目         |
| 磁盘驱动器         | 整理针对磁盘的操作入口               |
| 自定义扩展名       | 只处理 `.txt` 等指定文件类型的菜单   |

例如，一个网盘入口可能同时出现在文件和文件夹菜单中。只关闭文件场景里的项目，并不意味着文件夹场景也会消失，需要分别检查。

对于不常使用的入口，优先使用启用／禁用开关。之后如果改变主意，通常可以回到同一位置重新开启，比直接删除更方便。

#### 2.整理“新建”菜单

一些软件会在“新建”菜单中注册自己的文件类型，使用一段时间后，这个子菜单可能堆积很多很少创建的格式。

通过“新建菜单”页面，可以查看并管理相关条目。按自己的工作习惯保留常用格式，隐藏很少使用的项目，能明显减少查找入口的时间。

管理“新建”条目不会删除磁盘上已有的同类文件。需要注意的是，新建某种格式所需的模板或关联软件仍必须存在，工具本身不会自动提供所有文件格式的创建能力。

#### 3.整理“发送到”和“打开方式”

“发送到”适合保留常用目的地，也可以添加指向常用目录或程序的快捷入口。例如，经常把文件整理到某个资料目录，就可以考虑将该目录加入“发送到”。

“打开方式”则适合检查应用入口，整理不再需要或已经失效的项目。

这两类菜单的用途不同：前者把选中的对象交给目标处理，后者用于选择打开文件的程序。管理其中的菜单条目，也不等于修改 Windows 设置中的所有默认应用关联。

#### 4.定位菜单来源

遇到看不懂的菜单名称时，最有价值的功能往往不是删除，而是确认它来自哪里。

对于支持这些操作的项目，可以查看或跳转到：

- 对应的注册表位置。
- 关联程序或文件的位置。
- 菜单执行的命令。

软件还提供“菜单分析”，用于分析指定文件对象的右键菜单所在位置。当同一个入口在多个场景中出现，或者普通列表里不容易找到时，可以利用它辅助定位。

它也能帮助排查卸载软件后的菜单残留，但不是完整的软件卸载清理器。定位到注册表项或文件，不代表它们就一定可以删除。

#### 5.修改名称、图标与自定义命令

对于支持编辑的菜单项，可以调整显示文字、图标和执行命令，让常用入口更容易辨认。

还可以新建菜单项目，把常用程序与当前选中的文件关联起来。例如，为文本文件添加一个“用记事本查看”的入口，点击后把文件路径传给记事本。

不同类型的菜单实现方式不一样，并非每个项目都支持全部编辑功能。操作菜单里实际出现哪些选项，以对应项目为准。

### 四、下载与运行

#### 1.选择官方下载入口

可以从以下发布页下载：

- [GitHub Releases](https://github.com/BluePointLilac/ContextMenuManager/releases)
- [作者在 README 中提供的 Gitee Releases](https://gitee.com/BluePointLilac/ContextMenuManager/releases)

在 GitHub 发布页展开 `Assets`，可以找到：

```text
ContextMenuManager.zip
ContextMenuManager.NET.3.5.exe
ContextMenuManager.NET.4.0.exe
```

官方建议下载 ZIP，也可以直接下载对应的 EXE。不要把自动生成的 `Source code` 压缩包当作软件本体。

#### 2.选择合适的.NET版本

| 环境                                     | 选择建议                                     |
| ---------------------------------------- | -------------------------------------------- |
| Windows 7 原有 .NET 3.5 环境             | 可选择 .NET 3.5 版                           |
| Windows 8／8.1／10，已有 .NET 4.x 环境   | 可选择 .NET 4.0 版                           |
| Windows 11，已有 .NET Framework 4.x 环境 | 可尝试 .NET 4.0 版，但菜单功能仍需验证兼容性 |
| 缺少对应运行环境                         | 根据提示安装微软官方 .NET Framework 组件     |

这里的“.NET 3.5／4.0”指运行框架版本，不是软件的功能等级，也不是 CPU 的 32 位／64 位版本。

#### 3.解压并启动

将压缩包完整解压到一个方便管理的位置，例如：

```text
D:\Tools\ContextMenuManager\
```

运行适合当前环境的 EXE，按系统提示授予权限。普通用户无需克隆仓库或安装开发环境，直接使用发布程序即可。

建议保留软件及其配置、备份文件。部分增强菜单依赖配置目录中的辅助文件，启用后随意移动这些文件可能使对应菜单失效。

### 五、第一次使用：先隐藏几个不常用入口

可以从一个明确的目标开始，例如“隐藏文件右键菜单中不常使用的某个软件入口”：

1. 先在资源管理器里对一个普通文件右键，记下要处理的菜单名称。
2. 打开 ContextMenuManager，进入对应的文件菜单场景。
3. 找到该项目，必要时查看文件位置或命令，确认所属软件。
4. 使用项目旁的开关将其禁用。
5. 关闭已经展开的右键菜单，再对同类文件右键验证。
6. 如果需要恢复，回到相同位置重新启用。

Windows 11 用户请同时检查“显示更多选项”中的经典菜单。如果文件菜单已经改变，而文件夹菜单没有变化，应再检查文件夹对应的场景。

部分修改需要重启文件资源管理器才能生效，程序会提供相关提示。先保存工作并结束正在进行的文件操作，再使用“重启文件资源管理器”；也可以稍后注销或重启 Windows。

桌面和任务栏在资源管理器重启时可能短暂消失、重新出现，属于正常过程。

### 六、添加一个自定义菜单示例

下面以给 `.txt` 文件添加“用记事本查看”为例。它适合用来理解菜单文本、程序路径和命令参数之间的关系。

1. 在文件类型相关页面选择“自定义扩展名”，指定 `.txt`。
2. 使用“新建一个菜单项目”入口，选择单级菜单。
3. 将菜单文本填写为“用记事本查看”。
4. 通过浏览按钮选择记事本程序，核对命令参数。
5. 保存后，对一个测试用的 `.txt` 文件右键，检查新增入口。

Windows 安装在 C 盘时，可参考下面的填写方式：

| 字段               | 示例                              |
| ------------------ | --------------------------------- |
| 菜单文本           | `用记事本查看`                    |
| 菜单命令／程序路径 | `C:\Windows\System32\notepad.exe` |
| 命令参数           | `"%1"`                            |

`%1` 表示当前选中的文件，双引号用于处理路径中的空格。浏览选择程序后，工具可能已自动补上该参数，检查一次即可，不要重复添加。

如果程序安装位置不同，应使用实际路径。这个示例只针对文件场景；文件夹和空白区域的菜单参数不同，不能直接照搬。

### 七、禁用、删除与备份要分清

日常整理主要使用“禁用”。“删除此项”会移除对应注册信息或文件，恢复条件取决于具体项目及备份是否存在。

对提供“导出注册表”的项目，可以在修改前导出相关 `.reg` 文件。程序还提供“删除菜单时自动备份注册表”设置，但它并不意味着所有文件型菜单或所有修改都有完整备份。

需要恢复时，先确认备份对应的菜单及时间，再按情况导入相关注册表备份并刷新资源管理器。注册表备份不会恢复已经删除的程序文件，也不能代替原软件的重新安装。

第一次使用时，建议保留“打开”等基础操作。误改文件或文件夹的默认打开命令，可能影响双击行为；仅整理第三方附加入口，通常更容易检查结果。

### 八、常见问题

| 问题                           | 排查方向                                                         |
| ------------------------------ | ---------------------------------------------------------------- |
| 已禁用，右键菜单仍然存在       | 检查是否选错场景，或同一软件注册了多个入口；按提示重启资源管理器 |
| Windows 11 新菜单没有变化      | 到“显示更多选项”中检查经典菜单，不要假定新版菜单也受同样机制控制 |
| 项目显示启用，但实际右键看不到 | 菜单可能受文件类型、关联程序、系统条件或其他显示规则限制         |
| 禁用后在工具里也找不到项目     | 检查是否开启了“隐藏已禁用的菜单项目”                             |
| 以前被其他工具关闭的项目找不到 | 不同工具禁用方式不同，先用原工具恢复，再统一管理                 |
| 自定义菜单点击后没有反应       | 检查程序路径、参数、引号，以及被操作的文件类型                   |
| 卸载某个软件后还有菜单残留     | 查看对应文件和注册表位置，确认失效来源后再处理                   |
| 软件更新后菜单又出现了         | 对应软件可能重新注册了入口，优先检查其自带的右键集成设置         |

官方也建议避免同时使用多个右键菜单管理工具，以免不同的隐藏、备份和删除方式互相影响。

### 九、推荐结语与项目地址

ContextMenuManager 值得推荐的地方，是它把分散在不同位置的传统右键菜单整理成了可以查看、启停和编辑的列表。“按场景管理”“整理新建与发送到”“定位菜单来源”这几项功能，已经能覆盖大部分日常需求。

如果你的右键菜单已经堆积了很多很少使用的入口，可以先从隐藏少量项目开始。确认效果后，再尝试名称、图标或自定义命令，让菜单更贴近自己的使用习惯。
