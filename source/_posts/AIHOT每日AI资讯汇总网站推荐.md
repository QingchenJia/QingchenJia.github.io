### 一、为什么推荐AIHOT

关注 AI 行业，最容易遇到的问题是信息太分散：模型发布在官网，产品更新在开发者博客，讨论散落在社交平台，同一条新闻还会被不同媒体反复转述。每天逐个翻看这些渠道，往往花了不少时间，却很难快速弄清楚哪些变化值得关注。

[AIHOT](https://aihot.news/) 是一个汇总 AI 行业动态的网站，由数字生命卡兹克创建。它从多个信息来源采集内容，借助大模型筛选、评分并整理中文标题和摘要，再将相关报道聚合成事件，生成热点与每日资讯汇总。

它适合作为日常了解 AI 动态的入口：**先通过精选和日报掌握重点，再沿着感兴趣的事件阅读原始资料。** 对经常关注新模型、AI 产品和行业变化的开发者、产品经理及普通爱好者，都比较实用。

- 网站地址：[https://aihot.news/](https://aihot.news/)
- GitHub 仓库：[KKKKhazix/AIHOT](https://github.com/KKKKhazix/AIHOT)

除了看资讯，网站还提供 **Tibo 重置监控、模型排行榜、主题大事记，以及 RSS 和 Agent 接入**。如果你经常使用 AI 编程工具，这些功能也值得单独收藏。

_图 1：AIHOT 官网首页截图。上方可以切换内容分类，中间展示热点，下面的卡片包含来源、中文摘要、AI 评分与推荐理由。_

### 二、精选与热点：先看重点，再追踪事件

#### 1.先筛选，再阅读

资讯聚合最怕只是把更多链接堆到一起。AIHOT 的处理流程包含预筛、两次独立评分，以及按信息来源级别设置的入选门槛，目的是从采集到的内容中挑出值得阅读的部分。

入选内容会整理为中文标题、摘要和推荐理由。面对外文资料或篇幅较长的报道，可以先了解核心内容，再决定是否继续深入阅读，减少逐篇打开网页的负担。

首页还提供“一手、模型、产品、行业、论文、教程、观点”等筛选入口，以及标题、摘要搜索。想找实践内容时切到“教程”，想看模型发布时切到“模型”，比在全部动态中反复翻找更直接。

这里的“精选”来自项目设定的评分标准，**资讯卡片上的 AI 评分评价的是内容的入选价值，不是新闻所提到模型的能力分数**。模型能力另有专门的排行榜。

#### 2.把重复报道整理成事件

一个模型发布之后，官网公告、媒体解读和社交讨论可能同时出现。如果按文章逐条阅读，很容易在同一件事上反复花时间。

AIHOT 会判断不同报道是否属于同一事件，并把后续进展关联起来。这样可以围绕“发生了什么、后来有什么变化”来阅读，而不只是浏览一串相似标题。

项目的热度计算也围绕事件展开，综合独立来源的参与情况并加入时间衰减。同一来源反复报道不会简单累加成更高热度，热点列表更适合用来观察哪些事情正在受到多方关注。

[热点榜](https://aihot.news/hot) 展示过去 48 小时内受到多方讨论的事件，并标注趋势变化。进入事件页，可以继续看相关报道时间线和 AI 综述，把一次发布、后续开放及实际反馈连起来理解。

可以按下面的顺序阅读一个热点：

1. 先读事件标题和综述，了解发生了什么。
2. 查看最新进展，判断是否出现了新的功能、开放范围或其他变化。
3. 沿报道时间线回看前因后果，区分最初公告与后续解读。
4. 对准备实际使用的产品，继续打开原始来源确认条件。

### 三、日报、周报与月报：把信息流变成固定阅读

对不想持续刷新信息流的读者，日报是很实用的阅读方式。AIHOT 将内容整理为每日要闻，让读者可以集中浏览当天值得关注的变化。

![AIHOT日报的往期目录、头条、今日看点与栏目导航](../AIHOT每日AI资讯汇总网站推荐/daily.png)

_图 2：官网日报页面截图。左侧按日期查看往期，正文以头条和分栏方式编排，右侧提供今日看点与本期版面入口。_

日报采用类似报纸的排版：先展示头条，再按产品发布、行业动态、论文研究、技巧与观点等栏目组织内容，并提供来源和原文入口。顶部还能看到本期事件数、来源数及预计阅读时间，便于决定先略读还是完整阅读。

几种阅读方式可以按需要搭配，出刊时间均为北京时间：

| 入口                               | 更新或出刊方式  | 适合的需求                   |
| ---------------------------------- | --------------- | ---------------------------- |
| 精选                               | 动态进入信息流  | 随时发现值得点开的内容       |
| [日报](https://aihot.news/daily)   | 每天 08:00      | 每天集中浏览重点             |
| [周报](https://aihot.news/weekly)  | 每周一 10:00    | 回顾一周变化，补上漏看的消息 |
| [月报](https://aihot.news/monthly) | 每月 1 日 10:30 | 梳理一段时间内的重要进展     |

日报按规则编排已经筛选和整理过的内容；周报、月报再从日报中汇编，并由模型生成总述和栏目导读。每天阅读日报、周末回看关注的主题，已经能覆盖不少日常信息需求。

### 四、Tibo重置监控：集中查看Codex额度相关消息

#### 1.它在监控什么

经常使用 Codex 的用户，可能会关注临时额度重置或重置卡发放的消息。这类信息有时来自 Tibo 的公开帖子，预告、补充说明和确认又可能分散在不同回复里。

[Tibo 重置监控](https://aihot.news/codex-reset) 专门跟踪网站所介绍的 OpenAI Codex 负责人 Tibo（[@thsottiaux](https://x.com/thsottiaux)）发布的相关动态，将中文摘句、适用范围、预计生效时间及原帖链接整理到一个页面。

![AIHOT的Tibo重置监控状态、历史统计、重置日历与原帖](../AIHOT每日AI资讯汇总网站推荐/tibo-reset.png)

_图 3：官网 Tibo 重置监控截图。顶部显示状态与原帖，中间是历史统计，下方通过日历区分额度重置、重置确认和发重置卡。_

它比较实用的地方包括：

- **时间统一为北京时间**：不用自己反复换算帖子里的太平洋时间。
- **预告和确认分开显示**：可以看出一条消息是等待落地，还是已经有确认依据。
- **历史日历**：点击日期，查看当天的重置、发卡记录和关联原帖。
- **保留消息上下文**：中文摘句配合英文原文及引用内容，便于核对适用范围。
- **显示检查状态**：页面提供最近检查时间，网站说明每 10 分钟检查一次公开帖子。

#### 2.怎样读懂页面状态

使用时尤其要区分下面几种情况：

| 页面信息               | 应怎样理解                                         |
| ---------------------- | -------------------------------------------------- |
| 已宣布，等待生效       | 已有相关预告，仍需等待后续落地                     |
| 应已生效               | 按预计时间推算，尚未看到确认；不能当成已确认到账   |
| 已生效                 | 有官方确认或账户到账核实等依据，需查看具体说明     |
| 发重置卡               | 记录发卡消息，不等于额度已经恢复                   |
| 当前没有等待生效的重置 | 没有正在等待落地的已知预告，不代表能预测下一次重置 |

**这是 AIHOT 整理的第三方监控页，不是 OpenAI 的账户用量页面。** 它不会读取你的个人剩余额度，也不会替你触发重置；实际额度与重置卡余额需要在 Codex 内查看。

历史统计中的重置间隔中位数可以用于回顾，但不能当作固定周期。确认帖发布时间也不等于精确到账时间，阅读时应结合原帖和自己的账户状态。

#### 3.推荐的查看顺序

1. 从左侧“模型”分组进入“Tibo 重置监控”，先看顶部是否有待生效消息。
2. 点击日历中的相关日期，查看是额度重置还是重置卡发放。
3. 核对适用范围、中文摘句和英文原帖，确认消息是否与自己的使用情况有关。
4. 最后回到 Codex 查看个人用量，决定是否继续安排任务。

### 五、模型排行榜：结合能力、评测覆盖与价格选模型

[AIHOT 模型榜](https://aihot.news/leaderboard) 将第三方评测机构的成绩汇总展示，提供综合、编程、科研、专业办公和知识问答等榜单，也可以筛选国产模型或开源模型。

![AIHOT模型榜的领域切换、模型筛选、评测覆盖与API参考价格](../AIHOT每日AI资讯汇总网站推荐/leaderboard.png)

_图 4：官网模型榜截图。除了名次和 AIHOT 评分，还能比较上线日期、评测覆盖及缓存、输入、输出价格。_

按照网站公布的规则，榜单采用第三方机构统一实测的成绩，不纳入厂商自报分数；不同评测先折算到同一尺度，再按领域加权。想了解细节，可以查看[评测来源](https://aihot.news/leaderboard/sources)和[排序规则](https://aihot.news/leaderboard/rules)。

挑选模型时，建议一起看下面几项：

| 信息                 | 参考方式                                               |
| -------------------- | ------------------------------------------------------ |
| 领域榜单             | 写代码优先看编程表现，知识工作则结合专业办公或知识问答 |
| 评测覆盖             | 查看参加了哪些测试，避免仅凭少量测试推断全面能力       |
| AIHOT 评分           | 用于该榜单内比较，不应直接理解为答题正确率             |
| 输入、输出及缓存价格 | 估算 API 使用成本，注意计价单位为每百万 Token          |
| 评测原始成绩         | 对重要选型回到模型详情及原始榜单核对                   |

价格不参与榜单排序，订阅费用也不等于表中的 API 价格。可以先用榜单缩小候选范围，再拿自己的代码库、文档或日常任务做比较，选择更符合实际需求的模型。

### 六、主题大事记与收藏：持续跟进关心的方向

在[主题页](https://aihot.news/topics)，可以按公司与模型、技术方向、内容形态查找资讯。例如关注 AI 编码、图像生成、开源生态或某一家公司的动态，不必每次重新搜索关键词。

部分公司和技术方向的主题页还提供“大事记”。它将重要发布与进展整理成时间线，下方继续展示相关精选，适合同时了解历史脉络和最近变化。教程、观点等主题则直接阅读对应内容。

实际使用时，可以把与自己工作相关的两三个主题加入浏览器书签：

- 开发者可以关注 AI 编码、Agent 智能体、MCP 与工具调用。
- 做视觉创作的用户可以关注图像生成、AI 视频和多模态。
- 跟进产品变化时，可以直接访问对应公司的主题页。

遇到暂时没空阅读的文章，也可以使用网站的收藏功能。[收藏页](https://aihot.news/starred) 无需登录，数据保存在当前浏览器中，支持导出和导入备份。更换设备或清理浏览器数据前，先导出需要保留的收藏。

### 七、RSS与Agent接入：把资讯放进自己的工作流

#### 1.用RSS阅读器订阅

RSS 是一种内容订阅格式，阅读器可以集中获取多个网站的更新。如果已经使用 Folo、Inoreader 等工具，可以直接订阅 AIHOT，不必每天单独打开网页。

| 订阅内容 | 地址                                                    |
| -------- | ------------------------------------------------------- |
| 精选摘要 | [feed.xml](https://aihot.news/feed.xml)                 |
| 日报     | [feed/daily.xml](https://aihot.news/feed/daily.xml)     |
| 周报     | [feed/weekly.xml](https://aihot.news/feed/weekly.xml)   |
| 月报     | [feed/monthly.xml](https://aihot.news/feed/monthly.xml) |

在阅读器中选择添加订阅，粘贴需要的地址即可。建议先订阅“精选摘要”或“日报”，根据阅读量再决定是否添加其他入口；两者都订阅时可能看到同一事件的不同整理形式。

更多分类订阅和全文订阅方式可在[RSS 接入页](https://aihot.news/agent?tab=rss)查看。全文订阅也只对允许转载的来源附上正文，其他内容仍提供摘要与阅读入口。

#### 2.让Agent帮你查资讯

[Agent 接入页](https://aihot.news/agent) 提供 Skill、MCP、RSS 和 REST API 四种方式。其中 Skill 是供 Agent 使用的技能包，MCP 是让支持该协议的 AI 工具调用外部服务的连接方式，REST API 则适合自己编写脚本取数。

![AIHOT的Agent接入页面与Skill、MCP、RSS、REST API四种方式](../AIHOT每日AI资讯汇总网站推荐/agent.png)

_图 5：官网 Agent 接入页面截图。可以根据正在使用的客户端，选择技能包、远程 MCP、RSS 或 API。_

这些读取接口支持匿名只读访问，不需要申请 AIHOT API Key。接入后，可以让 Agent 帮你查精选、热点、日报、周报、月报，以及 Tibo 的重置动态，例如：

```text
过去 24 小时 AI 圈最重要的 5 件事是什么？
请给出中文摘要，并保留 AIHOT 阅读链接和原始来源。

最近一周有哪些值得关注的 AI 编码工具更新？

Tibo 最近有没有发布 Codex 额度重置消息？请区分预告和确认。
```

使用支持远程 MCP 的客户端时，可在其服务配置界面添加官网提供的 Streamable HTTP 地址：

```text
https://aihot.news/api/mcp
```

具体配置按[官网 MCP 接入说明](https://aihot.news/agent?tab=mcp)操作；使用 Skill 的读者可以按接入页提示安装，然后用上面的自然语言问题验证。模型榜目前通过网页查看，不要把网页上的全部功能都理解为已经提供给 Agent 的查询能力。

### 八、也可以用模板搭建自己领域的资讯站

AIHOT 的另一个亮点是公开了网站引擎和框架，包括采集、筛选、写作、事件聚合、日报生成及后台管理等能力。**如果你关注的不是 AI，而是法律、金融、教育或其他特定领域，也可以基于这个模板开发自己的动态资讯汇总网站。**

官方仓库提供了 [Use this template](https://github.com/KKKKhazix/AIHOT/generate) 入口，以及[“把它改成你的行业”指南](https://github.com/KKKKhazix/AIHOT/blob/main/docs/customize.md)。改造主要围绕以下几个方面：

- **网站名称与品牌**：修改 `site/site.ts` 等配置，使用自己的站名、介绍和 Logo。
- **信息来源与分类**：在 `industry/` 中调整初始信源、分类、标签和主题；运行后也可以通过后台管理信源。
- **筛选与写作标准**：修改 `industry/prompts/` 中的提示词和 `industry/selection.ts` 中的门槛，让系统知道本领域哪些消息重要、哪些内容应当过滤。

例如，做一个法律资讯站，可以围绕法规发布、重要判决和监管动态选择来源，并降低营销软文的入选机会。真正值得投入精力的地方，是挑选可靠信源和校准筛选标准，让汇总结果符合目标读者的需求。

仓库附带的是示范信源，并不包含线上站点的完整信源名单和运营数据。**模型榜、Tibo 重置监控和主题大事记等 AIHOT 专属功能也不包含在开源模板中**，不能直接把部署模板等同于复制整个官网。

自行部署需要准备运行环境及模型 API，具体可参考[官方部署文档](https://github.com/KKKKhazix/AIHOT/blob/main/docs/deploy.md)。代码采用 MIT 许可证，但 AIHOT 的名称和 Logo 不在许可范围内，搭建新站时应换成自己的品牌。
