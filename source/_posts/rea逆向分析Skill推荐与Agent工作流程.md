### 一、想知道一个软件怎么实现某个功能？

用软件时，你可能会好奇：它的搜索为什么这么快？点击“导出”之后，文件是怎么生成的？如果没有源码，想回答这些问题，就得从安装包、程序文件和运行过程里找线索，这也是逆向分析常做的事情。

[rea](https://github.com/morluto/rea) 的全称是 **Reverse Engineer Anything**。它能让 AI Agent 调用逆向分析工具，查看程序内部结构，再帮你梳理某个功能是怎样实现的。这里的 Agent，就是能够读文件、调用工具并完成任务的 AI 助手。

rea 还提供了一个叫 `reverse-engineer-anything` 的 Skill。你可以把它理解为给 Agent 准备的“办事指南”：先看什么文件，找到线索后查哪里，哪些地方需要实际运行验证，最后怎样把结果讲清楚。

如果你想研究自己拥有或获准分析的软件、学习某个功能的实现，或者比较新旧版本的区别，rea 就很值得了解。手里已经有完整源码、只想看懂项目结构时，直接让 Agent 阅读代码通常就够了。

### 二、Skill和分析工具分别负责什么

第一次接触时，容易把“安装 Skill”和“装好逆向工具”当成一回事。实际上，它们各有分工：

| 组成                              | 可以怎样理解               | 负责什么                                 |
| --------------------------------- | -------------------------- | ---------------------------------------- |
| `reverse-engineer-anything` Skill | 给 Agent 的操作指南        | 告诉它分析顺序、工具用法和整理结果的方法 |
| rea MCP 服务                      | Agent 和分析工具之间的接口 | 让 Agent 发起分析，并拿到结果            |
| rea CLI                           | 在终端使用 rea 的入口      | 让你通过命令直接分析文件                 |
| 分析引擎与辅助工具                | 实际干活的工具             | 完成反编译、拆包或运行观察等工作         |

MCP 是一种让 Agent 连接外部工具的协议。接入 rea 后，Agent 就可以通过它调用分析工具。至于该从哪里查起、下一步做什么，则由 Skill 提供指导。

不同任务需要的工具也不同。例如，深入分析编译后的程序，可能要用 Hopper、Ghidra 或 IDA；查看 JavaScript/Electron 应用的代码结构，就不需要这些引擎。rea 在本地分析文件，分析结果会交给 Agent；使用云端模型时，这部分结果也可能发送给模型服务。

### 三、rea能帮你做什么

#### 1.查看不同类型的软件和文件

| 分析对象                   | 能帮你看什么                           | 需要留意什么                                |
| -------------------------- | -------------------------------------- | ------------------------------------------- |
| 可执行程序、动态库         | 函数大致在做什么，哪些函数互相调用     | 深入分析通常需要 Hopper、Ghidra、IDA 等工具 |
| JavaScript、Electron、ASAR | 代码分成哪些模块，界面怎样调用后台功能 | 静态分析不需要原生反编译引擎                |
| .NET 程序集                | 程序中的类型、方法和指令               | 可以直接进行静态检查                        |
| Android APK                | 应用配置、类、方法及相互引用           | 代码分析需要 JADX 和完整 JDK                |
| ZIP、IPA、MSIX 等包        | 包里有什么文件，配置和资源放在哪里     | 适合先找出值得深入查看的部分                |
| 网站与运行中的应用         | 页面、脚本、网络请求和指定操作的记录   | 需要对应的浏览器或运行环境                  |
| HAR、SAZ 等网络记录        | 之前记录了哪些请求，返回了什么内容     | 读取已有记录时不会重新发送这些请求          |
| 固件等其他文件             | 文件结构、组成部分和可提取的内容       | 部分能力需要额外工具或特定系统              |

这里的“静态分析”，就是先读文件、不运行目标程序。ASAR 则是 Electron 常用的打包格式，桌面应用的代码可能就放在一个 `app.asar` 文件里。

#### 2.顺着一个功能往下查

比起一次看完整个程序，更实用的做法是带着一个问题开始。例如，想知道“导出文件”怎么实现，rea 可以帮助 Agent：

- 从按钮文字、接口名或通信通道入手，找到相关代码。
- 顺着模块之间的关系，继续查到负责处理和保存数据的部分。
- 比较新旧版本，看看相关代码或文件发生了什么变化。
- 需要时观察实际操作，把“代码看起来会这样做”和“运行时确实这样做”对照起来。
- 保存分析记录，让下一次调查接着已有结果继续。

反编译得到的代码通常是便于阅读的近似表达，并不等于找回了原始源码。它能帮你理解实现思路，具体行为仍要结合其他线索判断。

### 四、怎样安装和接入

#### 1.第一次使用，建议走配置向导

先准备 Node.js 和 npm，并核对[官方运行要求](https://github.com/morluto/rea/blob/main/docs/installation.md#package-runners-and-global-installation)。仓库列出的 Node.js 范围是：22.x 至少 22.23.4，24.x 至少 24.22.1，或 26.12.1 及以上；预发布版本不在支持范围内。

打开终端，在自己信任的工作目录中运行下面的命令。不要直接进入待分析的软件目录下载 npm 包。

```powershell
npx rea-agents@latest setup
```

1. 选择要使用 rea 的 Agent，例如 Claude Code、Codex 或 Cursor。
2. 查看向导准备修改哪些配置、备份放在哪里，以及 Skill 安装到哪里。
3. 确认后，向导会配置 MCP 连接，并安装配套的 Skill。
4. 按分析任务准备需要的工具，例如填写已有 Ghidra 或 IDA 的安装位置。
5. 按向导提示重启 Agent，就可以开始提问了。

向导可以在单独确认后安装 Hopper，其他工具如 Java、Ghidra、IDA、JADX 等仍需自行准备。如果 Windows 提示不能运行 `npx.ps1`，可以把命令里的 `npx` 换成 `npx.cmd`。

#### 2.只想安装Skill，也有单独的命令

如果已经配好了分析工具，只需要给 Agent 加上工作指南，可以使用：

```powershell
npx skills add morluto/rea --skill reverse-engineer-anything
```

这条命令只安装 Skill 和参考资料，不会配置 MCP 连接，也不会装好分析引擎。第一次使用时，优先选择前面的 `setup` 更容易把需要的部分配齐。通过客户端插件安装的方式，可以参考文末的官方安装文档。

如果 Agent 读到了某个工具的说明，却实际调用不了，也可能是 Skill 和服务版本没有对应上。此时应检查连接和版本，按当前可用的工具继续处理。

### 五、Agent会按照什么顺序工作

```text
先问清楚要查什么 → 选对工具 → 看整体结构
→ 顺着线索找代码 → 必要时运行验证 → 记下结果和疑问
→ 回答最初的问题，需要时再编写和测试实现
```

#### 1.先弄清楚要查什么

1. 把大问题拆小，例如“导出按钮在哪里处理”“数据怎么传过去”“文件最后由谁保存”。
2. 找准应用和文件路径；如果只说“分析我的软件”，Agent 还需要知道具体是哪一个。
3. 看看之前有没有分析过，能否接着已有记录继续。
4. 明确这次只读文件，还是也需要运行程序、操作网页或编写代码。

如果工具已经连好，就可以直接开始。Skill 并不要求每次都重新检查和安装一遍；遇到工具缺失或连接失败，再针对问题排查即可。

#### 2.根据文件类型选工具

- 拿到 Electron 的 ASAR 文件，就用 `analyze_javascript_application` 查看应用结构。
- 拿到可执行程序或动态库，就从 `open_binary` 开始，再调用需要的分析工具。
- APK、.NET 程序集、网页和网络记录也有各自的入口，Agent 按 Skill 的说明选择。

不用记住这些名称，也不需要把它们输入终端。它们是 Agent 调用的工具，你主要负责提供正确的目标和问题。

#### 3.先看大概，再查细节

1. 先看程序的整体结构。对于较大或不知道大小的 JavaScript 应用，优先让工具返回摘要。
2. 从结果里找出与问题相关的模块或函数，同时留意还有哪些内容没分析到。
3. 复用已有分析记录，只查看接下来需要的部分。
4. 找到按钮文字、接口名等具体线索后，再继续追踪相关代码。

工具返回的 `parent_evidence_id` 可以理解为完整分析记录的编号。Agent 可以用它调用 `inspect_analysis_view`，分批查看细节，不必每次从头分析。返回摘要能减少一次读到的内容，但不一定减少工具在后台做的分析。

找到明确线索后，Agent 还可以调用 `trace_application_feature` 追踪功能。不过，搜索到或关联到某个模块，只能说明值得查看，不能马上认定它参与了这个功能。

#### 4.光看代码不够时，再运行看看

1. 先判断问题能不能靠读文件回答，例如某个函数里有没有一段处理逻辑。
2. 如果想知道“点击之后到底发了什么请求”，就需要观察实际运行过程。
3. 根据任务要求操作目标，记下用了什么环境、做了哪些动作、得到了什么结果。
4. 把运行结果和之前看到的代码对照，检查自己的解释是否说得通。

这一步很好理解：代码里有一段逻辑，不代表刚才点击按钮时就执行了它。运行观察也会真的启动或操作程序，rea 的捕获功能本身不会把程序放进安全沙盒。

#### 5.把“看到了”和“猜测的”分开写

Skill 很重视这一点：Agent 需要说明 **哪些是直接看到的，哪些是根据线索推测的，哪些还不知道**。每条重要结论还应带上分析记录的编号，也就是 Evidence ID，方便回头核对。

以 Electron 为例，界面和主进程之间常通过 IPC 传递消息。IPC 就是进程间通信，可以把它理解为软件不同部分之间的“传话方式”。

| 情况                 | 更容易理解的表达                                   |
| -------------------- | -------------------------------------------------- |
| 在文件里看到了线索   | 这段代码里出现了一个 IPC 通道名，位置在这里        |
| 根据线索作出推测     | 两处代码的通道名唯一匹配，它们可能是发送和接收双方 |
| 实际运行时看到了结果 | 在这次测试操作中，记录到了对应调用或响应           |
| 还没查清楚           | 通道名是在运行时拼出来的，目前还没找到它发给谁     |

没查清的问题可以用 `record_unknown` 记下来，找到答案后再更新。某次搜索没搜到，也应该写成“这次检查的范围里没找到”，而不是直接说“软件没有这个功能”。

#### 6.问题多时，分开查、一起整理

如果一次要研究好几个功能，Agent 应列出问题清单，逐项记下查到了什么、依据在哪里、还有什么疑问。代码之外，配置文件和资源也可能影响结果，需要一起查看。

如果使用的工具支持多个 Agent 同时工作，可以把互不依赖的问题交给不同的子 Agent，也就是分担任务的 AI 助手。它们共享已有记录，分别返回发现和疑问；需要前一步结果才能继续的问题，则按顺序处理。

#### 7.最后检查有没有回答你的问题

1. 回看最初的清单，说明哪些已经回答，哪些只查清了一部分，哪些还没解决。
2. 用容易理解的话讲清功能流程，并给出可以核对的来源。
3. 如果你要求做一个类似功能，再根据调查结果编写代码，说明哪些地方是参考原程序、哪些是新设计。
4. 按选定的输入和预期结果测试。即使 `verify_reconstruction` 验证通过，也只说明这些检查通过了，不能代表所有情况下都与原程序相同。
5. 需要下次继续用的记录先导出保存；打开过原生程序分析会话的，完成后用 `close_binary` 关闭。

### 六、可以怎样给Agent下任务

假设你想研究自己的 Electron 应用怎样导出文件，可以把下面这段提示词发给已经接入 rea 的 Agent。`preload` 是 Electron 的预加载脚本，常用于连接界面与主进程能力。

```text
请使用 reverse-engineer-anything Skill 和 rea 分析这个文件：
D:/Apps/DemoApp/resources/app.asar
我想弄清楚：点击“导出文件”后，程序怎样把数据保存成文件？
1. 先读文件，找到界面入口、preload 脚本和相关 IPC 通道。
2. 接着已有分析结果往下查，不要重复分析相同内容。
3. 告诉我哪些是直接看到的，哪些是推测的，并标出来源。
4. 如果需要启动应用，先说明想验证什么、准备做哪些操作。
5. 最后用中文讲清整个流程，把还没查清的问题单独列出来。
```

使用时，把示例路径换成实际 `app.asar` 的绝对路径。这个例子只是演示怎样提问，具体使用了哪些模块和通信通道，需要 Agent 读取你的文件后才能知道。

如果暂时不想配置 Agent，也可以先在可信目录中用终端命令分析这个文件：

```powershell
npx -y rea-agents@latest analyze-javascript-application "D:/Apps/DemoApp/resources/app.asar" --json
```

这条命令不需要 MCP 连接或原生反编译引擎；Linux 上还需要 PATH 中有兼容 procps 的 `ps` 命令。它会输出 JSON 格式的分析记录，你可以再让 Agent 帮忙阅读，继续追查自己关心的功能。

### 七、为什么值得试试rea

如果你经常想弄懂一个软件的某项功能，rea 可以帮你把读文件、找代码、看运行结果这些工作串起来。Agent 按 Skill 一步步查，你可以跟着它给出的来源核对，也能让它接着上次没查完的地方继续。

初次使用，建议挑一个小问题，例如“导出按钮最后调用了哪个函数”。等这条流程走通，再研究更大的功能。这样既容易上手，也更容易看出 Agent 有没有真正回答你的问题。
