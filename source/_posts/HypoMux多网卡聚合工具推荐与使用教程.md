### 一、为什么推荐HypoMux

电脑连接着有线宽带，手机还有可用的移动网络，下载大型游戏或镜像文件时，能否让两条网络同时出力？

Windows 同时连接多张网卡，并不意味着下载任务会自动把它们的带宽加起来。大部分应用仍按系统路由选择出口，额外的网络可能长期处于闲置状态。

[HypoMux](https://github.com/Hypostasis-Cat/HypoMux) 是一款面向 Windows 的开源多网卡聚合与分流工具。它可以将多个网络连接分配到不同网卡，让有线、Wi-Fi、手机热点和 USB 网络共享共同承担下载流量，并通过图形界面管理调度策略、分流规则与网络诊断。

我推荐它的主要原因，是它把“多条网络如何一起使用”变成了普通用户可以操作的桌面功能。对于经常下载大型游戏、系统镜像或开发资源，而且手头确实有多个可用网络出口的人，值得尝试。

安装与使用以 Windows 11 为例；下文不将官方演示或理论带宽作为本机实测结果。

### 二、先理解它能提升什么

#### 1.聚合的是多个连接

HypoMux 的核心方式是**连接级负载分配**：下载软件建立多个连接时，分别安排它们使用不同网卡。

例如，电脑同时拥有一条 300 Mbps 宽带和一条可用速率约 100 Mbps 的手机网络。下载任务有足够多的并发连接、服务器供给和本机性能也足够时，总吞吐量就有机会超过仅使用宽带的水平。

这只是原理示例，不表示一定能达到 400 Mbps。实际效果还受网络波动、下载源限速、连接数量、无线环境、磁盘和 CPU 等因素影响。

| 情况                                            | 合理预期                     |
| ----------------------------------------------- | ---------------------------- |
| 多连接下载，同时有多个独立网络出口              | 有机会提高整体下载吞吐量     |
| 只有一条 TCP 下载连接                           | 仍受该连接所用线路的速度限制 |
| 网线和 Wi-Fi 都连接同一台路由器、共用同一条宽带 | 无法凭空增加宽带出口容量     |
| 两张网卡分别连接不同宽带或宽带与移动网络        | 更有可能发挥多出口的价值     |
| 希望降低所有游戏的延迟                          | 聚合本身不保证降低延迟       |

同一路由器下的有线与无线，即使可能缓解某一段本地链路瓶颈，最终仍共享上游带宽。因此，尝试前应先弄清楚：自己有的是“两张网卡”，还是“两条相对独立的网络出口”。

#### 2.适合哪些人

- 经常使用 IDM、Steam、Epic 等进行多连接下载。
- 电脑已有宽带，愿意用手机网络补充下载能力。
- 希望让下载软件、会议软件和其他程序使用不同网络。
- 需要查看各网卡的流量、连接数和线路状态，排查网络瓶颈。

如果只有单一网络出口，或者主要诉求是让单连接任务提速，HypoMux 的聚合收益通常有限。手机共享网络还会消耗套餐流量，适合根据实际资费决定是否加入聚合池。

### 三、有哪些值得关注的功能

#### 1.两种接入模式

| 模式            | 工作方式                                                  | 适用场景                                     |
| --------------- | --------------------------------------------------------- | -------------------------------------------- |
| 系统代理        | 提供本地 HTTP/HTTPS、SOCKS5 代理，可接管 Windows 系统代理 | 浏览器、下载器等支持代理的应用               |
| 虚拟网卡（TUN） | 通过虚拟网卡接管更广泛的 TCP/UDP 流量                     | 不遵循系统代理的应用、游戏平台下载及复杂分流 |

初次使用可以先尝试系统代理模式，确认多条线路能正常工作；应用没有使用代理、需要更广泛的流量接管时，再考虑虚拟网卡模式。

系统代理模式不会创建虚拟网卡，但覆盖范围取决于应用是否遵循代理设置。TUN 模式依赖 Core 服务以及相应网络组件，对其他 VPN、虚拟网卡与路由设置的兼容性要求更高。

#### 2.按用途分流

HypoMux 支持根据进程、域名和 IP/CIDR 配置规则，将连接交给聚合引擎、直连，或指定某张网卡处理。

比较实用的安排是：让大型下载使用聚合，让会议和语音程序走稳定线路；需要固定出口的服务，也可以指定网卡，减少不同连接使用不同公网出口带来的影响。

v2.7.0 还增加了拒绝连接规则与规则集订阅。订阅支持 Clash payload YAML 和 sing-box source JSON 中受支持的匹配类型，并不表示兼容这两类工具的所有规则语法。

#### 3.调度策略与实时状态

当前版本提供轮询、手动权重、自适应速度和低延迟优先等策略。

| 策略       | 可以怎样理解                                           |
| ---------- | ------------------------------------------------------ |
| 轮询       | 在可用线路间依次分配新连接，便于观察基础聚合效果       |
| 手动权重   | 按自己设定的倾向分配新连接，适合已知线路能力差异的情况 |
| 自适应速度 | 根据持续吞吐等信息逐步调整新连接分配                   |
| 低延迟优先 | 结合延迟、抖动和丢包探测选择线路                       |

权重主要影响连接分配，不是精确的带宽限速，也不保证流量严格按某个百分比分摊。策略调整不会把已有 TCP 连接直接搬到另一条线路。

软件还会展示各网卡速率、连接数、总吞吐和活动连接，便于判断任务是否进入引擎、是否真正使用了多个出口。

### 四、下载安装

#### 1.准备环境

本文对应的官方正式版支持 **Windows 10/11 x64**。准备至少两条可以独立联网的连接，例如：

- 有线宽带 + 手机 Wi-Fi 热点。
- 有线宽带 + 手机 USB 网络共享。
- 两个不同网络出口，通过两张网卡连接电脑。

先分别验证每条线路能访问网络，再让它们同时连接。手机 USB 共享通常便于与现有 Wi-Fi 并用，但能否稳定工作仍取决于手机、驱动和数据线。

#### 2.下载官方安装包

打开以下任一官方发布入口：

- [GitHub Releases](https://github.com/Hypostasis-Cat/HypoMux/releases/latest)
- [腾讯 CNB 官方镜像](https://cnb.cool/Hypostasis-Cat/HypoMux/-/releases/latest)

下载 `HypoMux_Setup_*.exe`。本文核对版本的文件名为 `HypoMux_Setup_2.7.0.exe`；以后安装时以正式发布页为准。

两处官方渠道分发同一份签名安装包，官方说明中的签名发布者为 **SignPath Foundation**。普通用户使用安装程序即可，无需克隆仓库，也不需要安装 Go、Node.js 或自行编译。

#### 3.完成安装并启动

双击安装包，选择安装位置，按向导完成安装；系统请求权限时按提示操作。安装程序会部署桌面端与所需 Core 组件。

HypoMux 的桌面界面以普通用户权限运行，涉及 TUN、路由、DNS 等高权限网络操作时，由独立 Core 服务处理，不需要让整个界面长期以管理员身份运行。

### 五、第一次使用：从选网卡到开始下载

#### 1.选择参与聚合的网卡

启动 HypoMux，在首页刷新网卡列表，勾选准备参与聚合的活动网卡。

例如，选择“以太网”和手机 USB 共享对应的网卡。网卡名称由设备与驱动决定，不一定直接显示“手机”；可对照 Windows 网络设置，确认每张网卡对应哪条线路。

只选择这次要使用的有效出口，不要把 VPN、虚拟机等创建的虚拟接口误当成独立互联网线路。

#### 2.先运行网络体检

运行界面中的“网络体检”，查看各条线路是否有有效 IPv4、网关、DNS，以及是否具备源地址绑定能力。

如果某条线路单独上网就有问题，先处理该线路，再测试聚合。这样更容易区分是原始网络故障，还是应用没有进入 HypoMux。

#### 3.选择模式与策略

第一次测试，建议先选择系统代理模式，并使用轮询策略观察各网卡能否分担连接。

需要让不遵循系统代理的应用进入引擎时，停止当前聚合，再切换到虚拟网卡模式，按界面提示完成检查。需要调整设置的操作是否可以即时生效，以当前版本提示为准。

#### 4.开启引擎，再启动下载

开启聚合引擎后，再启动 IDM 多连接下载或游戏平台下载任务。如果 Steam 已经运行，按 HypoMux 界面提示重启 Steam，使代理设置完整应用。

应用需要手动填写代理时，官方 README 给出的默认本地端口是：

| 代理类型        | 地址        | 默认端口 |
| --------------- | ----------- | -------- |
| HTTP/HTTPS 代理 | `127.0.0.1` | `10801`  |
| SOCKS5 代理     | `127.0.0.1` | `10800`  |

端口可以因配置而变化，请以软件实际设置为准。使用 Windows PowerShell 时，也可以用以下命令检查 HTTP 代理入口是否能访问网站：

```powershell
curl.exe --proxy http://127.0.0.1:10801 -I https://www.microsoft.com
```

这只能验证一次代理请求是否可用，不能用来证明带宽已经叠加。真正评估聚合效果，需要产生多个连接并观察持续吞吐。

#### 5.观察连接与速率

在 HypoMux 中查看各网卡的连接数和实时速率，再打开 Windows 任务管理器的“性能”页面作对照。

出现多个网卡同时有流量，说明任务可能已在多个出口之间分配；还应结合活动连接确认是不是目标下载任务，排除系统更新或其他后台程序的流量。

使用完成后，先停止聚合，再正常退出软件，让程序恢复接管的系统代理与网络设置。如果之前在下载器里手动填写了本地代理，也要自行取消或切回原配置。

### 六、如何配置一个实用的分流方案

假设电脑有一条稳定宽带，以及一条速率会波动的手机网络，可以从下面的安排开始：

| 应用或任务               | 建议安排                     | 原因                     |
| ------------------------ | ---------------------------- | ------------------------ |
| Steam、IDM 大文件下载    | 聚合出口                     | 利用多个连接分担下载流量 |
| 语音会议、远程办公       | 指定稳定宽带，或根据需求直连 | 优先保持稳定性           |
| 对公网出口变化敏感的服务 | 指定固定网卡                 | 减少不同连接使用不同出口 |
| 暂时不希望参与聚合的程序 | 直连规则                     | 保持其正常网络路径       |

在分流页面按进程、域名或目标 IP 添加规则，选择对应动作；保存后按照界面提示应用，必要时重新启动 TUN。

“直连”表示绕过聚合调度，并不等同于一定使用某张物理网卡。如果目的就是让会议软件始终使用宽带，应明确指定该网卡，并通过活动连接核实出口。

对于竞技游戏，建议先使用直连、指定稳定线路，或暂停聚合。低延迟优先策略可以辅助选线，但不能保证游戏延迟下降，也不能保证线路变化时现有会话不断开。

### 七、怎样判断是否值得长期使用

建议用同一个下载源进行对照，而不是只看一次测速峰值：

1. 单独使用线路 A，记录稳定阶段的下载速度。
2. 单独使用线路 B，用相同条件再次测试。
3. 同时启用两条线路和 HypoMux，保持下载方式与并发设置一致。
4. 对比持续速度、完成时间、CPU 与磁盘占用，并观察是否频繁断流。

尽量避免其他设备或后台任务抢占带宽，必要时重复几轮。Steam 下载还可能受解压和磁盘写入限制，下载源变化、缓存和运营商拥塞也会影响对比结果。

注意单位：宽带标称常用 `Mbps`，下载器可能显示 `MB/s`，理论换算约为 `8 Mbps = 1 MB/s`，实际传输还存在协议开销。

如果增加手机线路后只是消耗了额外流量，完成时间没有明显缩短，可以停用该线路；如果多个常用下载任务都获得稳定收益，再考虑将它作为日常工具。

### 八、其他功能与常见问题

#### 1.可以后续尝试的功能

- **Steam 下载节点优选**：评估候选节点并提供相关状态，效果受地区、线路和下载源影响。
- **实验性聚合热点**：先启动 TUN 聚合，再进入“工具箱 → 聚合热点”，设置热点名称、密码和频段，让其他设备连接。需要支持 Windows 移动热点的无线网卡；热点已开启不代表共享出口或提速效果已经验证。
- **MTU 检测与恢复**：帮助排查指定网卡到目标地址的路径问题。首次安装不必为了“优化”立即修改 MTU。
- **AI 助手与小 Mux**：可查询状态并辅助操作，但需要自行配置支持工具调用的模型服务；对话和必要工具结果会发送到所选服务，可能产生 API 费用。基础聚合功能无需启用它。

#### 2.常见问题速查

| 问题                          | 优先检查                                                         |
| ----------------------------- | ---------------------------------------------------------------- |
| 只有一张网卡有流量            | 任务是否只有少量连接、另一线路是否可用、规则是否固定了出口       |
| 开启后下载没有变化            | 应用是否进入代理或 TUN、下载源是否限速、两张网卡是否共用一个上游 |
| 速度提升后又下降              | 手机信号、线路拥塞、下载连接更替、磁盘写入或解压是否成为瓶颈     |
| 系统代理设置反复变化          | 是否有另一个代理客户端同时接管系统代理                           |
| TUN 启动冲突                  | 其他 VPN/TUN 是否正在接管默认路由，查看软件诊断提示              |
| 停止 HypoMux 后某应用不能联网 | 应用是否还手动指向已停止的 `127.0.0.1` 代理端口                  |
| 游戏或会议体验变差            | 改为直连、指定稳定线路，或暂停聚合后对照测试                     |

HypoMux 提供了一些第三方代理与游戏加速器的兼容旁路，但仍应避免两个程序同时争用系统代理，或让两个 TUN 同时接管默认路由。出现问题时，先简化为 HypoMux 与两条正常网络，再逐步恢复其他软件，通常更容易定位原因。

### 九、推荐结语与项目地址

HypoMux 值得推荐的地方，在于它把多网卡连接调度、应用分流和诊断整合到一个可操作、可观察的界面中。对已有多个独立网络出口、下载任务又能产生多个连接的 Windows 用户，它提供了一种提高网络利用率的实用选择。

初次体验只需完成“连接两条网络 → 安装官方版本 → 选择网卡并体检 → 开启聚合 → 对比下载效果”。确认基本收益后，再逐步使用权重、规则和其他功能。
