### 一、问题现象

在使用 Codex CLI 时，如果网络代理没有正确接管终端流量，可能会遇到请求一直失败、自动重试，最后提示类似“请求 5 次重连仍然失败”的问题。

常见表现包括：

- Codex 启动正常，但发送请求后长时间无响应；
- 终端中反复出现 retry、reconnect、connection failed 等提示；
- 浏览器可以正常访问相关网站，但 Codex CLI 仍然无法稳定连接；
- 同一台电脑上，ChatGPT 网页端可用，命令行工具不可用。

这类问题通常不是 Codex 本身安装错误，而是终端程序的网络流量没有走到正确的代理链路。

### 二、原因分析

很多代理客户端默认使用的是系统代理模式。系统代理通常只对支持 HTTP、HTTPS 或系统代理设置的应用生效，浏览器大多能自动识别，所以网页访问看起来没有问题。

但 Codex CLI 运行在终端中，它的网络请求不一定完整遵循系统代理设置。尤其是在 Windows PowerShell、Windows Terminal、VS Code 终端、WSL 或某些 Node.js 网络请求场景下，可能出现浏览器能走代理，而 CLI 工具没有走代理的情况。

因此，当 Codex 请求 OpenAI 服务时，如果流量没有进入代理，就会出现连接失败、请求超时或多次重连失败。

### 三、解决方法：切换为 TUN 模式

最直接的解决方法是把当前计算机的代理模式切换为 **TUN 模式**。

TUN 模式会在系统网络层创建虚拟网卡，并接管更多应用的网络流量。相比只依赖系统代理，它对命令行工具、开发工具、终端程序和不主动读取系统代理配置的软件更加稳定。

切换后，Codex CLI 的请求会更容易被代理客户端正确接管，从而解决“请求 5 次重连”的问题。

### 四、操作步骤

不同代理客户端的界面名称略有差异，但思路基本一致。

#### 1. 打开代理客户端

先打开当前正在使用的代理工具，例如 Clash Verge、Clash for Windows、Clash Meta、Mihomo Party 或其他支持 TUN 的客户端。

#### 2. 找到 TUN 模式开关

一般可以在以下位置找到：

- 设置；
- 系统设置；
- 网络设置；
- 内核设置；
- Service Mode；
- TUN Mode。

如果客户端要求安装服务模式、虚拟网卡或网络扩展，按提示完成安装。Windows 上通常需要管理员权限。

#### 3. 开启 TUN 模式

开启 TUN 模式后，建议同时确认：

- 代理节点已连接；
- 规则模式或全局模式已按需要配置；
- DNS 设置没有报错；
- 虚拟网卡状态正常；
- 客户端没有提示内核启动失败。

如果不确定规则是否覆盖 OpenAI 相关域名，可以先临时切换到全局模式测试。

#### 4. 重启终端和 Codex

TUN 模式开启后，关闭当前 PowerShell、Windows Terminal 或 VS Code 终端，然后重新打开。

进入项目目录后再次运行：

```bash
codex
```

如果是非交互任务，可以重新执行：

```bash
codex exec "你的任务描述"
```

### 五、验证是否恢复

可以从下面几个角度确认问题是否解决：

- Codex 不再连续提示重连失败；
- 请求响应速度恢复正常；
- 能够正常登录、提问、读取项目并返回结果；
- 切回普通系统代理模式后问题复现，重新开启 TUN 模式后恢复。

如果仍然失败，可以继续检查：

- 当前节点是否可用；
- 代理客户端日志里是否有 OpenAI 或 Codex 请求记录；
- 本机防火墙是否拦截了代理客户端或虚拟网卡；
- 是否同时开启了多个代理工具导致路由冲突；
- 是否需要重启代理客户端或电脑。

### 六、补充说明

TUN 模式解决的是“命令行流量没有稳定进入代理”的问题。它并不会改变 Codex 的账号、模型、额度或安装状态。

如果 Codex 报错内容明确是认证失败、额度不足、账号不可用或命令不存在，就不属于本文讨论的 5 次重连问题，需要分别检查登录状态、订阅额度和安装环境。

日常使用中，如果浏览器可以访问但 CLI 编码工具经常连接失败，可以优先检查代理是否处于 TUN 模式。对于 Codex、Claude Code、OpenCode、Gemini CLI 这类终端 Agent，TUN 模式通常比单纯系统代理更稳定。

### 七、结论

Codex 出现请求 5 次重连失败时，优先不要反复重装 Codex，也不要急着怀疑账号问题。更常见的原因是当前终端流量没有被代理正确接管。

对应的解决方法很简单：

```text
将当前计算机的代理模式切换为 TUN 模式，然后重启终端重新运行 Codex。
```

如果切换后 Codex 恢复正常，就说明问题主要出在代理接管范围，而不是 Codex CLI 本身。
